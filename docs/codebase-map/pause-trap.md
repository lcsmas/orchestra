# Fleet Pause — the host trap (#252 D1b) and the Pause douce (#254)

The **host's reaction** when a run becomes HARD-paused (a **Pause douce** reaches this trap only once it escalated — see §Pause douce below). Design: `docs/adr/0003-fleet-pause-host-enforced-on-the-bus.md` +
`CONTEXT.md` §Pause. The state, the switch, the verbs and every entry-point GATE are D1a's (`src/main/bus-pause.ts`,
`src/main/pause-gate.ts`, schema = `MIGRATIONS[9]` in `src/main/bus.ts`); this doc is what happens to the **members' worktrees
and processes** once `runs.paused_at` is set. Wave D ledger #261 (D4 = the destructive-act rules below).

## What it does, in order (per member of the paused run and every descendant run)

`trapMember` (`src/main/pause-trap.ts:141`; members run in parallel, bounded by `deps.concurrency`, default 3) — every step records its own failure in the Bilan and the trap moves on:

1. **Read what it is doing** (`activityOf`): surface (structured/pty/none), turn running, in-flight tool calls (a live SDK session's own open `tool_use` set — `Session.openToolUses`, folded by the pure `applyToolEvent`/`mergeInFlight` of `src/shared/open-tools.ts`, authoritative; the hook-fed tracker only when there is no SDK session; the command text comes with it), background tasks — BEFORE anything is interrupted.
2. **Snapshot** the worktree to `refs/orchestra/pause/<run>/<ws>/<ms>` (`snapshotWorktree`, `src/main/pause-snapshot.ts:297`): a
   TEMPORARY index (`GIT_INDEX_FILE`, seeded from a copy of the real one, rebuilt from HEAD if the copy is torn) → `git add -A` into it →
   `write-tree` → `commit-tree -p HEAD` → `update-ref`. The worktree, the REAL index, HEAD and every branch are byte-identical
   before/after (D4; every git call runs `GIT_OPTIONAL_LOCKS=0`, none reads-then-rewrites the real index). Captures tracked edits,
   staged work and untracked non-ignored files; untracked files > 25 MB are left out and REPORTED, and when ALL untracked work exceeds 1 GiB the largest UNITS are dropped too (`total-cap`, `selectSkipped`, linear): a wholly-untracked directory (`git ls-files --others --directory` CHOOSES the unit; its SIZE comes from the plain non-ignored listing, so an ignored `node_modules` next to new source is never counted or dropped with it) is ONE unit and ONE directory exclude — no tracked file lives below it, so no tracked edit is lost, and a 240k-file un-ignored tree costs one exclude (the per-file version took 150 s and froze the main process). The Bilan keeps the largest 200 entries + a count (`skippedLargeCount`); the scan yields to the event loop; more than 50 excludes (or a non-UTF8 name) go through `--pathspec-from-file` in the TEMP dir (never the worktree), git < 2.25 (a USAGE error: exit 129 + "unknown option" on stderr — never a timeout, never the command text) falls back to 200 argv excludes and says the rest ARE in the ref (`snapshotNotes`); a `git add` TIMEOUT (120 s) throws `SnapshotTimeoutError`: no fallback, no rebuild, no ref — the Bilan records `snapshotIncomplete: 'timeout'` and the pause still interrupts and kills (any git call that times out — ls-files, add, update-ref… — is the same named outcome; a timed-out snapshot is never re-taken on a retry; the listing falls back to a HEAD-seeded temp index on a torn real index; git runs with `LC_ALL=C`) (no silent truncation at 200); ONE unreadable file does not abort the snapshot (`git add --ignore-errors`: the rest is captured, the file is named in
   `snapshotWarnings`); checked-out submodules (`.git` FILE) are snapshotted in their own repo (`submodules[]`); a nested standalone repository (`.git` directory) is left untouched and reported. Untracked/ignored semantics = plain `git add -A`.
3. **Bilan de pause row** (`pause_records`, `src/main/bus-pause-records.ts:124`) written BEFORE any process is touched, so the snapshot
   ref is durable even if the app dies next; `killed_json` stays NULL until step 5 (NULL = "owed", so a boot drain finishes it without a 2nd snapshot).
4. **Arm + interrupt**. `arm` attaches the member's idle detached keeper (only a live, started, not-shutting-down one — `sdkAttachIfDetached` would KILL a
   never-started keeper, which D4 forbids) so its CLI-started turns are observed. `sdkInterruptForPause` (`src/main/agent-sdk.ts:4017`) then interrupts the running
   turn with a PLAIN interrupt: **the queue is never dropped** (queued AUTO prompts stay parked by `promptStream`'s pause hold and run after the lift; a HUMAN
   prompt still runs first). PTY agents get ESC. Never stops the CLI session or the keeper. A turn running in a DETACHED keeper this app run never attached to
   is attached first (attaching starts no turn). An idle session (no running or CLI-started turn) is left alone.
5. **Kill the tool process trees** (`killToolTrees`, `src/main/pause-kill.ts:220`) under a CLI whose identity was proven (keeper argv + the CLI is the
   keeper's child). Result → `killed_json`. The killer re-checks the pause before EVERY round and signal (`stillPaused`, review F8) and only reaches processes older than a HUMAN turn
   whose tool ROOT started inside a HUMAN turn's window (`humanWindows`, a getter re-read at every signal; the window closes when the turn ends (an OPEN window with no human turn in flight any more is clamped to now), so a background task a short human prompt started stays shielded and one started after the end is not — D9, round-3 F3i; the interrupt skip needs the turn in flight NOW; compared on the tool ROOT's start — for env orphans the earliest start along their ppid chain — so a pre-pause rig's later forks die with it; process start = `now − (uptime − ticks/CLK_TCK)`, `startWallMs` — the floored `btime` read ~0.4 s early and killed a human turn's first processes): a human prompt sent while the trap runs — even one queued behind other members — is neither interrupted nor has its tools killed.
   A lift landing while the trap arms / probes the CLI stops it BEFORE the interrupt; a lift mid-kill still records what was killed.
6. **UNKNOWN is not NONE (review F4/F10).** A tracked keeper that is alive but did not answer the probe, an unprovable CLI, a failed/timed-out interrupt, ZERO members or a store not
   loaded from disk leave the member's `killed_json` NULL and the trap UNSTAMPED: retried by the sweep (with backoff, 5→60 s); the last attempt's error stays visible in `run status` until the retry's
   own write; a retry keeps the FIRST attempt's was-doing, snapshot facts and interrupt (a fresh read says "idle"); a `cliOf` error defers the interrupt to the retry (the pauser is only recognisable through a proven CLI — a probe flake must never interrupt it) — at most `MAX_INTERRUPT_DEFERRALS` (3) attempts, then it runs anyway, EXCEPT for a pauser an earlier attempt already proved (`exempt:'pauser'` + `pauserCli` carried on the row: never interrupted while its CLI is unreadable). A CLI that vanished/was replaced mid-kill (`cliGone`) leaves the member incomplete with a note; kills of an incomplete attempt are kept (`earlierKilled`). Retries back off 5→10→20→40→60 s (`pauseRetryDelay`) and warn once per pause. `arm` has a 15 s deadline (a hang is unknown ⇒ retried; a rejection is only
   recorded); an alive keeper with an unreadable argv is 'unknown', never "no keeper". Only a proven member is complete.

Then `runs.pause_trap_at` is stamped (guarded on `paused_at`, so a trap that outlived a resume + re-pause cannot stamp the NEW pause) — only when EVERY member is complete. A lift mid-trap
stops the trap before the next process is touched. The snapshot runs with `core.hooksPath=/dev/null` (the repo's hooks never fire, review F6). **The pauser (review F5) is keyed on PROCESS ANCESTRY, never the `--as` handle.** The CLI records the `orchestra run pause` process chain at pause time
(`src/main/pause-origin.ts`, stored as a reserved `pause_records` row `__pause_origin__` — no schema change; a recent pause waits ≤3 s for it). The member whose CLI (pid + /proc
start-time re-verified against the live CLI) is an ancestor is the pauser: its turn is NOT interrupted and ONLY the tool tree that holds the call (`spareRoots`) is spared — its other
trees (a background task…) are killed; it is still snapshotted, armed and recorded (`exempt: pauser`). A human typing `--as <coordinator>` in a plain shell exempts NOBODY. No origin /
a recycled CLI pid in the chain ⇒ nobody is spared.
A CLI-started turn on the pauser is a new turn and IS trapped (rows 29/30).

## Destructive-act rules (D4) — `src/shared/pause-procs.ts`

- **What is a tool**: a direct child of the CLI that is a shell run with `-c` (how the CLI runs Bash-tool commands, background tasks and hooks) + its ppid
  tree (`planToolTrees`, `:163`). MCP servers and other non-shell children are **spared and listed** (`spared`). Measured on CLI 2.1.284: each tool shell
  leads its own session (sid = pid) and exports `CLAUDE_PID=<cli pid>`; a foreground tool's abort kills its whole session, a **background task survives an
  interrupt** (only the trap kills it), and a job that started its own session (`start_new_session`) survives everything but the trap's provenance rule.
- **Identity re-read AT SIGNAL TIME** (`verifyAtSignal`, `:295`): fresh `/proc/<pid>/stat` read immediately before EVERY signal (SIGTERM, then again before SIGKILL):
  start-time equals the planned one, not a zombie, the CLI is still the same process, and a lineage proof — root ⇒ still a child of the CLI; member ⇒ ppid chain
  hop by hop, else same session as its root, else env provenance (`CLAUDE_PID == this CLI` AND started after it, re-read now). **Unreadable ⇒ refused
  (fail closed)**; the CLI, the keeper, the app and pid ≤ 1 are refused by a separate check even from a forged plan. Non-Linux: no start-time identity → nothing is killed.
- Kill order: deepest first, roots last; SIGTERM, ≤2 s grace, SIGKILL for the same-identity survivors; ≤3 re-plan rounds (a tool started while killing is caught); survivors are reported, never hidden.
- **Another session's supervisor is never a tool (review F1, pre-review M1/M2)**: an env-/session-proven orphan that is, has a descendant or has an ANCESTOR that is `keeper.js`, a `claude` CLI or the
  Orchestra/Electron main process is REFUSED and listed as `spared` (planner + signal-time ppid-chain re-read, an unreadable hop refuses; `supervisorAncestorOf`). `Orchestra.AppImage cli <verb>` (the `orchestra`
  CLI client) is NOT a supervisor. The sparing is orphan-only BY DESIGN (D4 literal: never the CLI/keeper of any session) and both sides are pinned: a tool's own `claude -p` / `node keeper.js` descendant IS killed, a daemonized `claude`-named orphan is spared (unit + real-process arms, signal-time pin). Real-pid arm: a daemonized app → another ws's keeper → its CLI → its MCP-like child, all carrying this CLAUDE_PID, survive. A dead prior root's recycled pid cannot vouch for an unrelated
  session (the root's planned start-time is required, review F9).
- **Orphans (LEAD ruling D11)**: a process that left the CLI's tree is killed only with provenance re-read AT SIGNAL TIME, fail-closed — `CLAUDE_PID` must name THIS member CLI's IDENTITY (pid + /proc
  start-time, re-verified just before the signal), never the bare pid, AND the process must have started after that CLI. Every killed process is listed in the Bilan with pid, cmdline, **cwd** (read before
  the signal) and **the reason matched** (`killed[].evidence` = the planner's reason + what the re-read proved; `run status` prints each orphan's line, every recorded string stripped of control characters). Real-pid must-FAIL arms
  (`scripts/pause-trap/provenance-inner.mjs`, pid namespace + `ns_last_pid`): (a) another member's orphan (its CLAUDE_PID names another CLI, even one started AFTER this CLI) survives; (b)/(c) a process whose
  CLAUDE_PID names a RECYCLED pid (the pid is now this CLI's) and that started BEFORE the CLI survives; control: the member's own daemonized orphan IS killed. Mutants `env-pid-not-matched` /
  `env-start-time-ignored` (each edits planner AND re-read — two layers cover each other) redden (a) / (b,c).
- **Known limits (NOT covered)**: a process that escaped BOTH the tree and the env marker (`env -i … &` after its shell died); containers (`docker run -d`); remote/sandbox members (recorded as not applicable); a pid recycled between the re-read and the `kill()` syscall (microseconds; no `pidfd` in Node); the turn observer's own kill (`onTurnStart`) has no human-turn cutoff; killing a background task makes the CLI send ONE task-notification model request before the observer interrupts it (recorded in the Bilan note, not prevented); with the store loaded but 0 live members the trap is retried with backoff (5→60 s) and `run status` reads NOT FINISHED; a workspace re-parented INTO a paused subtree after the stamp is never trapped; the origin walk cannot tell a worker a pre-pause daemon (tmux, a dev server) forked at a human turn's request from one it forked for the rig — the former dies with the daemon; `earlierKilled` keeps the last 100 kills (D11 "every killed orphan is listed" bends above that); the snapshot's git cost is ~files × excludes for per-file excludes (directories collapse; a TRACKED directory with ≳110k flat untracked files still pays it: the snapshot may TIME OUT — recorded `incomplete: timeout`, no ref, the pause goes on; the killed `git add` leaves unreachable loose objects in the member's `.git` and may orphan a clean-filter child until it exits); an app restart after a FINISHED trap re-arms a pauser whose exempt turn is still running and the observer may then interrupt it.

## Pause douce (#254, wave E ledger #276 D3/D4)

`orchestra run pause` WITHOUT `--hard` (`verbRunPause(…, 'soft')`, writer `setRunPause(…, mode)` `src/main/bus-pause.ts`) writes `pause_mode='soft'` + `pause_deadline_at = paused_at + 3 min` (`SOFT_PAUSE_DEADLINE_MS`,
frozen interface `src/shared/pause-lifecycle.ts`, schema `MIGRATIONS[10]`). Every existing GATE reads `paused_at`, so réveils / turns / spawns are refused AT ONCE; the state machine is `pausePhaseOf` (`pausing` → `paused` once `pause_escalated_at` is set).
`--hard` over a douce that is still waiting ESCALATES it (`escalated` outcome); a lift clears every pause column (`pause_deadline_at`, `pause_escalated_at`, `resume_started_at`, `pause_auto` too).

What the HOST does (`src/main/pause-douce.ts`; driven from `sweepPauseTrap` — the SAME detection as the trap: boot drain, WAL-dir watch, 15 s sweep — plus a one-shot timer armed at the earliest pending deadline, `armDouceTimer`, so the escalation lands AT 3 min):
1. **Enrol** every member in `pause_members` (`enrollMember`; role `coordinator` = the workspace `runs.coordinator` names, else `worker`; `member_run` = its nearest orchestrator). The upsert is a no-op when unchanged — a write would re-trigger the bus-dir watcher → sweep → write.
2. **A member with a turn RUNNING** (`TrapDeps.activityOf().turnRunning`) gets ONE `kind='pause'` bus row (sender `host`, recipient the member, in the member's own run; the row IS the dedupe) and a one-shot ORDER file `<events dir>/../pause-orders/<ws>.json` (`pauseOrderFiles`; one JSON string literal).
   **A member with NO turn running** is confirmed by the host (`host-idle`) — no wake. UNKNOWN is not NONE: an unreadable activity — or a tracked keeper that is alive but did not answer the probe with no session/PTY (`MemberActivity.unknown`, pure `keeperActivityUnknown` in `src/shared/pause-douce.ts`) — counts as running (order sent), an unloaded store enumerates nobody and never reads as "everyone confirmed". A sandbox member is `host-idle` at once (no turn the host can reach).
3. **Delivery at the next tool-result boundary — through the HOOK, not the prompt queue.** A structured session parks a mid-turn prompt until the turn ENDS (`promptStream` gate), so a bus wake could never reach a command-by-command turn in time. The posttool hook script (`ORCHESTRA_HOOK_SCRIPT`, `src/main/workspaces.ts`;
   `PostToolUse` + `PostToolUseFailure`) `mv`s the order file to `<ws>.taken` (once-only; its ctime is the delivery receipt) and prints `{"hookSpecificOutput":{"hookEventName":…,"additionalContext":<order>}}` — the real CLI 2.1.289 attaches that as a trailing `role:'system'` message (`PostToolUse:Bash hook additional context: …`) of the NEXT request only. One `stat` per tool call when there is no order. A member blocked inside ONE long command reaches no boundary: only the deadline takes it.
4. **The accusé**: `orchestra run confirm pause` (`verbRunConfirmPause`, store-less, identity `$ORCHESTRA_WS_ID`/`--as`) → `pause_confirmed_at` + `pause_confirm_via='member'`, first writer wins. The caller must BE a member: proven by the live-tree walk from its own workspace, or already in the epoch roster (the host enrols before it sends the order) — anyone else is refused (`not-a-member`, rc 1, nothing written: no phantom roster row, no forged "all confirmed"; arm `douce-forged`). `--as` stays caller-asserted, like every bus verb. Its carrier is the live-tree walk from the caller's own node (`pausedCarrierForWorkspace`), else `--run` / `$ORCHESTRA_RUN_ID`, else the ACTIVE pause whose roster holds the caller (`carrierFromRoster` — the host enrols before it sends the order). It also drops its own undelivered order.
5. **Escalation** (`pause_escalated_at`, `escalateSoftPause`, guarded on epoch + soft + still waiting): every member of the current enumeration confirmed (`all-confirmed`) OR `now ≥ pause_deadline_at` (`deadline`). `runsOwingPauseTrap` is now `trapOwed` (hard: at once; soft: once escalated) so the #252 trap takes EVERYONE next — confirmed members too (clean snapshot + Bilan, which the Reprise needs).
   The trap records each member it completes as `pause_confirm_via='trap'` unless it already has an accusé (`confirmByTrap`, `enrollRoster` — a hard pause gets a roster the same way).
6. While `pausing`, `armPausedMembers` does NOT attach keepers: an attach mid-turn reads as a CLI-started turn and the observer would interrupt the very command the douce lets finish. The escalated trap arms them itself.

Reading it: `orchestra bus-status` prints `pause: Pause douce en cours — N/M en pause — manquent : <name (id8)>, … — Pause dure à <iso> (dans Ns) pour les retardataires` (the `/busStatus` reply carries `pause` + `pauseLabels` only while paused, `busStatusPausePayload`); `orchestra run status` prints the same line + one line per roster member and "Host trap: NOT OWED YET" while waiting (`--json`: `roster`).
**Switch `pause` OFF ⇒ `run pause` is refused ⇒ none of the new columns/rows/files is written ⇒ the sweep (`softPausingCarriers` filters on the frozen switch) never acts, even on a stale soft row.**

Known limits (Pause douce): (1) the `pause` row stays pending in the member's mail after the lift, so each notified member is woken once to read an obsolete order (the D1a lift herd; the order text says "ignore this if the pause was lifted" and E2's Reprise supersedes the herd);
(2) while the douce is WAITING (`pausing`) the turn observer does NOT interrupt a turn that starts (an unexplained start there is most often a keeper reattach mid-turn after an app restart) — a cron/`/loop` turn runs until the escalation's trap takes it; a HUMAN prompt typed in the window spends its mark at its own start AND every human mark made before the escalation is void after it (`since = max(pausedAt, escalatedAt)`), so the first CLI-started turn after the escalation is trapped (arm `douce-humanmark`);
(3) the pauser (the coordinator whose own tool issued the pause) keeps its turn at escalation, as in a Pause dure;
(4) a member whose hook script predates this feature (rewritten only at its next workspace start) or a structured member with a live Raw terminal (`ORCHESTRA_WS_ID` withheld from its CLI) never reads the order: it is waited on until the deadline (nothing in bus-status says "order not delivered");
(5) a SUBAGENT's tool calls (payload `agent_id`) never take the order — it waits for the member's own next boundary; an order older than 5 min is dropped by the hook, never injected;
(6) "all paused" for a straggler = the deadline + the trap's own duration (the rig measures ≈ +0.4 s);
(7) nested douces: the member's accusé is recorded on its carrier AND on every outer carrier in an active pause; (8) a member archived mid-pause that never confirmed is dropped from the roster (a confirmed row is history).

Gates for the douce: `pnpm run test` — `src/main/pause-douce.test.ts` (writer/escalation/sweep/roster/hook, real bus + the REAL hook script), `src/cli/run-pause-douce.test.ts` (built CLI), `src/shared/pause-lifecycle.test.ts`; rig `pnpm run test:pause-trap -- --arm douce-…` (see the table below); in-place mutants in `scripts/pause-trap/mutate-unit.mjs` (`douce-*`).


## Detection (`src/main/pause-trap.ts`)

`startPauseTrap` (`src/main/pause-trap.ts:727`, called from `src/main/index.ts:566`, stopped at `:871`): a boot drain, a 15 s sweep, and a **directory** watch on the bus dir (the `-wal` inode is recycled —
same reason as `armBusWalWatcher`). `sweepPauseTrap` (`src/main/pause-trap.ts:681`) reads D1a's `runsOwingPauseTrap` (carrier paused, frozen `pause` switch ON, `pause_trap_at` NULL); concurrent sweeps trap a carrier once.
Members = non-archived workspaces with a worktree that the gate would call paused by this carrier: the carrier's anchor is self-or-ancestor on the LIVE store `parentId` chain
(`liveChainIncludes`, the same scope as D1a's `pausedCarrierForWorkspace`; `runSubtreeIds(carrier)` only as the fallback when the chain dangles — `parent_run_id` is write-once).
Every sweep also RE-ARMS (`armPausedMembers`, `src/main/pause-trap.ts:628`) each member of every ACTIVE pause, finished trap or not, so an idle keeper's CLI-started turn is observed after an app restart. **Switch OFF ⇒ `runsOwingPauseTrap` is empty ⇒ nothing happens.**
A pause that landed while the app was DOWN is drained at the next boot: the detached keepers kept running their tools meanwhile; the trap attaches, interrupts and kills.

## Rows 29 / 30 — a turn that starts on a paused member

`onTurnStart` (`src/main/pause-trap.ts:566`): a **CLI-started turn** (model output with no app-yielded turn in flight — `src/main/agent-sdk.ts:1422`; also the `submit` chokepoint, `src/main/activity.ts:957`;
e.g. `/loop`, cron, the task-notification a killed background task triggers) on a paused member (the observer asks the gate's own `pausedCarrierForWorkspace`) is interrupted, its tool trees killed, and the Bilan notes it; starts that land while the handler runs are coalesced into one re-run (none dropped); the start fired by the member trap's OWN `arm` attach is ignored (`trapArming`: the trap handles that member itself, pauser-aware, pre-review M9). A HUMAN turn is allowed and un-pauses nothing — exactly, without a timer: `sdkHumanTurnInFlight` (`session.gateTurnHuman`, set with the gate, cleared at both release sites; `humanTurns` itself is pruned at `emitQueueUpdate` before the gate opens) lets a human turn through however late the CLI's hook lands (a cold-started member; only a turn yielded AFTER the pause — one in flight at the pause is trapped), and the yield-time mark below stays as the fallback for a turn that already ended
(`markPauseHumanTurn`, `src/main/pause-trap.ts`: marked by `promptStream` (`src/main/agent-sdk.ts`) at the YIELD of a turn that contains a human prompt — the turn's real start, so a parked or second prompt is allowed when IT starts (review F2); one single-use mark per turn, 30 s TTL; a mark older than the PAUSE admits nothing). PTY agents — and a structured member with a live Raw terminal — are not observed (their human keystrokes also fire `submit`).

## Reading it

`orchestra run status [--run <id>] [--json]` (`src/cli/run-status.ts`, store-less; after the lift it still prints the LAST pause's Bilan — `pause_records` outlives `run resume`): paused by/since, the carrier (an inherited pause names the ancestor run to lift — resolved by the ONE exported `coverFor` in `src/cli/index.ts`, the live-tree walk `run resume` uses too, so a run re-parented after creation reads the same in both), trap done/owed, and per member: dirty tree, snapshot ref
(`git diff <head> <ref>` = the uncommitted non-ignored work), what it was doing, interrupt outcome, commands killed, survivors, refused, spared, notes, error. Reprise is NOT automatic: `run resume` starts the structured Reprise below — nothing restarts on its own, except a pause the host wrote itself on a usage-limit stop (`pause_auto`), Reprised when the quota is back (`accounts-usage.md` §Auto Pause on a usage limit, #256).

## Reprise — coordinators first, Consigne de reprise per member (#255, wave E E2)

`orchestra run resume` does NOT lift the pause: `beginReprise` (`src/main/bus-pause.ts`, signature = the frozen `RepriseEntry` of `src/shared/pause-lifecycle.ts`; body `beginRepriseCore`, `src/main/pause-reprise.ts` — a LEAF module that imports no `bus-pause*.ts`,
the callers pass `runSubtreeIds`; the roster is DECIDED by `planRoster` — one enumeration read by `seedRoster`, by `repriseAddressees` (who gets a `reprise` row, in which run) and by #256's auto-Pause wake guard) stamps `runs.resume_started_at` (phase `resuming`; `paused_at` stays), completes the roster (`pause_members`, which the Pause douce already enrolled at pause time) from the **LIVE workspace tree** — the same walk the gate and the trap use; `runs.parent_run_id` is write-once and a `runs` row outlives a demotion (review M3).
Every live orchestrator at/under the carrier is a `coordinator` (a re-parented or run-less OPS counts, a demoted ex-orchestrator does not — the live role OVERRULES the douce's bus-tree role in both directions; the bus run tree answers only for a workspace the live tree does not know — `liveStatus` = `under` the carrier / `elsewhere` (a COMPLETE chain that misses it: another wave ⇒ plain worker) / `unknown` (not in the tree, or its chain dangles at a deleted ancestor ⇒ the bus fallback applies)), every other member a `worker`;
`member_run` = the run the member belongs to (a coordinator's = the run it coordinates, the douce's convention; the run that RELEASES a coordinator is derived on the fly, `releaserRunOf`). A member of a PLAIN run-anchoring carrier (#221, no orchestrator on the chain) belongs to the CARRIER run (`runWithin`), never to a standalone run of its own. The live tree is registered by the host (`buildPauseTrapDeps`: the store) and by the store-less CLI (`store.json`: archived workspaces stay resolvable in `get`, only `ids()` drops them, like the host) through `setLiveTreeSource`. Upserts are no-ops on repeat (`WHERE differs`) — the sweep re-seeds on every pass and a write would re-trigger the bus-dir watcher.
It releases ONLY the coordinators in depth order (live chain length; `released_by='host'`) and sends each ONE `kind='reprise'` row (sender `host`, in the coordinator's own run) = its OWN Bilan + the Bilan de pause of ITS wave
(`renderCoordinatorReprise`: the workers of its run + the coordinators directly under it, one line each: snapshot ref · dirty tree · killed commands · calls the interrupt aborted, plus the `release` commands).
Outcomes: `no-run` · `not-paused` · `refused` (the hold rule — the carrier's coordinator or an ancestor run's; a HOST caller, E3's `{host:true}`, is never refused) · `already-resuming` (the stamp is an atomic `… AND resume_started_at IS NULL` update — nothing re-sent) · `resuming`.
A carrier whose frozen `pause` switch is OFF (a stale column) is lifted plain, as before wave E. The run closes (`finishRepriseIfDone`, one lock, epoch-guarded; EVERY pause column NULL incl. wave E's) when the whole roster is released — at once from `beginReprise` and from the last `release` ONLY when the
host trap had finished (`pause_trap_at` set ⇒ every member that existed at the trap has a Bilan row ⇒ the roster is complete for the paused fleet); otherwise the HOST sweep decides. A workspace that joins the tree LATER (e.g. a worker a released OPS spawns during the Reprise) is seeded BLOCKED by the sweep and released with `release --all`. A Bilan row without `memberRun` leaves `member_run` NULL (never a wrong default); the sweep fills it from the live tree.

- **The gate (`memberMayStart`)**: `pausedCarrierForWorkspace` skips a carrier that is `resuming` and has RELEASED this workspace (`releasedWhileResuming` = the frozen `memberMayStart` over the carrier's current phase + the member's roster row, same epoch only; two small reads, only when `resume_started_at` is set) and keeps walking — including in the dangling-chain fallback (`resolvePause(db, id, ws.id)`) — an ancestor carrier may still pause it. `{includeReleased:true}` is for the readers that need the carrier itself — `run status` (a RESUMING run reads "RESUMING … is being lifted by the Reprise", never "not paused" / "Last pause (LIFTED)"). `run resume` / `release` also name an ANCESTOR run that still pauses the inner run ("still PAUSED by run X — lift that one") instead of printing LIFTED / ACTIVE.
  Every gate site funnels through it, so the sdk start, wake, spawn, queue drain, usage-limit auto-resume, liveness roster and the trap's turn observer all agree. HUMAN origins stay allowed. The store-less twin (`activePauseForCoordinator`, run-level, the run's coordinator as member) serves `coverFor` when the app's store file is unreadable.
- **The trap stops at the Reprise**: `stillPaused` (pause-trap.ts) also requires `resume_started_at` NULL, and `runsOwingPauseTrap` goes through the pure `trapOwed` — a resuming carrier owes nothing and a Reprise landing mid-trap stops it before the next signal. - **Accusé (`orchestra run confirm reprise`)**: `confirmReprise` stamps `reprise_confirmed_at` on the NEWEST roster epoch of each carrier that RELEASED the caller (keyed on the workspace id, so it still works after the run went active); refused while not released.
