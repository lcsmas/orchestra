# Resource service (`packages/resource-service/`, binary `resctl`)

Standalone Linux command any swarm can call (spec #448, ADR 0013, ledger #464). **Imports nothing from the repo or any Orchestra module** — `packages/resource-service/test/no-orchestra-imports.test.ts` (scanner `packages/resource-service/test/lib/import-guard.ts`) fails on a relative path leaving the package, a specifier naming `orchestra`, any non-builtin package, a non-literal `import()`/`require()`, or a dependency in `package.json`. TypeScript runs by Node ≥ 22.18 type stripping (erasable syntax only, `.ts` import suffixes); `packages/resource-service/bin/resctl.mjs` is the entry.

Run it: `pnpm run test:resource-service` (package tests, `# skipped` must be 0), `pnpm run test:resource-service-mutants` (`packages/resource-service/scripts/mutants.mjs`, one `packages/resource-service/mutants/<ticket>.json` per ticket), typecheck `npx tsc -p packages/resource-service`. Keep `packages/resource-service/` out of the app's `tsc`/`vite` — it is not part of the Electron build.

## A1 — a declared run is cleaned after its coordinator dies (#449)

**Model.** A *run* is a caller-chosen id in `$RESCTL_STATE_DIR/state.json` (not a bus run). Liveness = the coordinator process, identity `pid + /proc/<pid>/stat` field 22 (`packages/resource-service/src/proc.ts:10` `readStat`, `:32` `isAlive`). Nobody renews anything. States `alive → grace → cleaned` (`packages/resource-service/src/state.ts:10`); a record carries a random `token` per run INSTANCE (added to the freeze: lanes get it as `RESCTL_RUN_TOKEN`).

**Verbs** (table `packages/resource-service/src/cli.ts:14`, exit codes `packages/resource-service/src/errors.ts:2`: 0 ok · 1 failure · 2 usage · 3 refused · 64 not implemented):
- `run start --id --owner <pid>` — `packages/resource-service/src/verbs/run-start.ts:16`. Same id: `alive` + same owner → no-op; `alive` + another LIVE owner → exit 3; `alive` + dead owner (reaper has not looked yet) or `grace` with `now < graceEndsAt` → **re-adopt** (same token, lanes kept, grace cleared); `grace` with `now ≥ graceEndsAt` → it is cleaned synchronously (`endRun`) then the id starts fresh; `cleaned` → fresh. Then `ensureDaemon` (`packages/resource-service/src/daemon.ts:17`) unless `RESCTL_NO_AUTOSTART=1`.
- `run end --id` — `packages/resource-service/src/verbs/run-end.ts:8`: cleans in the CLI (no daemon needed), returns only when nothing of the run is alive, idempotent (cleaned → 0), unknown id → 3.
- `exec --run <id> -- <cmd>` — `packages/resource-service/src/verbs/exec.ts:13`: the lane is a child of the CLI, `detached: true` (own session = own process group, pgid = pid), env gets `RESCTL_RUN`, `RESCTL_RUN_TOKEN`, `RESCTL_STATE_DIR`; recorded in `lanes`; SIGINT/SIGTERM/SIGHUP forwarded to the lane's group; exit code forwarded (`128+sig` for a signal, 127 command not found). A lane record is dropped on exit only when its whole group is gone (a marker-less survivor stays reachable through the group).
- `serve` — `packages/resource-service/src/verbs/serve.ts:9`: the reaper, foreground, holds `daemon.lock`, loops `tick` every `RESCTL_TICK`; exits 1 if its lock is taken over, 3 if another daemon holds it.
- `admit` (A3), `docker-env` (A2), `status` (A5): stubs, `not implemented (A<n>)`, exit 64 — the table is final, later tickets fill their own verb file.

**The reaper** (`packages/resource-service/src/reaper.ts`): pure `decide` (`:14`) — grace over at `now >= graceEndsAt`, `maxLifeAt` (consumed here, the `--max-life` flag is A6), purge of cleaned runs after `RESCTL_KEEP`; `tick` (`:23`) applies it: state changes under the state lock, **cleanup OUTSIDE the lock** (it waits seconds), then `endRun` marks THAT instance (token compared) `cleaned` only if every step succeeded; a failed step is retried next tick. Grace counts from when the reaper NOTICES the death, not from the death itself.

**Cleanup pipeline** (`packages/resource-service/src/cleanup.ts`): ordered `CLEANUP_STEPS` (`:65`; A1 = `kill-processes`; A2 appends `remove-containers`, A4 `stop-scopes`); a failing step does not skip the next. `collectRunProcesses` (`:14`, all members; `sendable` `:27` = the ones this process may signal) = members of the recorded lane groups **plus** every process whose environ carries `RESCTL_RUN_TOKEN=<token>` (`findByEnv`, `packages/resource-service/src/proc.ts:121`) — the group alone misses a `setsid`/double-forked child, the marker alone misses a child that exec'ed with an empty env; both are needed and both are tested. `killProcesses` (`:50`): TERM, wait `RESCTL_TERM_WAIT` (3 s), then KILL rounds; throws if something survives SIGKILL, and (`refuseIfBlocked` `:44`) if members of the run sit in the CALLER's own process group — `run end` run from inside one of the run's lanes fails loudly (exit 1) instead of reporting a clean run; the reaper, in its own group, is unaffected. `endRun` (`:86`) marks `cleaned` only if no lane registered while the steps ran (an `exec` racing the cleanup → another round, max 3); once `cleaned`, `exec` refuses to register and kills its own lane (`packages/resource-service/src/verbs/exec.ts:42-51`).

**Safety rules** (all in `packages/resource-service/src/proc.ts`): every signal re-reads identity right before sending (`signalIfSame` `:71`, `signalGroupIfOurs` `:107`); refuses pid ≤ 1, pgrp ≤ 1, the caller, and the caller's own process group (`mayTouch` `:60`); a group kill needs the recorded leader to be the same process still leading it, or gone while members remain (`groupIsOurs` `:84` — the kernel never reuses a pid that is still a group id). Never `pgrep -f`. Residual TOCTOU between the identity read and `kill(2)` (no pidfd in Node 22) is accepted.

**Locks** (`packages/resource-service/src/lockfile.ts`): the lock file is created whole with `link(2)`, holds `{pid,startTime}`, and is stolen ONLY after the holder fails the identity probe (dead, or pid reused → other starttime), re-reading the file right before the unlink (`tryAcquire` `:34`). Two stealers racing can briefly both believe they hold `daemon.lock`; the daemon re-checks `holds(lock)` each tick and exits, and reaping is idempotent. `state.lock` (via `withState`, `packages/resource-service/src/state.ts:47`) is the single writer of `state.json` (tmp + rename, mode 0600); a corrupt or newer-version file **fails closed** instead of reading as "no runs".

**State hygiene** (follow-up): `load` (`packages/resource-service/src/state.ts`) builds `runs` with a null prototype (ids like `constructor` are ordinary keys) and stamps the kernel `boot_id` (`bootId()`, `packages/resource-service/src/proc.ts`) into `state.json`; a file from ANOTHER boot closes every open run on load (recorded pid/pgid/starttime mean nothing after a reboot — never signalled). The reaper `tick` drops a lane whose group is gone or whose leader pid now belongs to a stranger. The import guard (`packages/resource-service/test/lib/import-guard.ts`) scans every JS/TS extension and refuses symlinks. Tests `stale-records.test.ts`, `autostart-in-lane.test.ts` (a daemon started inside a lane must not carry `RESCTL_RUN_TOKEN`).

**Non-obvious decisions**
- Re-adopt vs expiry use the same comparison on the same stored `graceEndsAt`, so a run is either re-adoptable or cleanable, never both.
- `RESCTL_RUN_TOKEN` (not `RESCTL_RUN=<id>`) is the sweep key: ids collide across state dirs and across a re-started same id; a token is per run instance. `RESCTL_RUN=<id>` is still exported for the lane's own use.
- `ensureDaemon` strips `RESCTL_RUN*` from the daemon env: a daemon started from inside a lane would carry the marker and be swept with that run.
- Limits: a lane that both `setsid`s and clears its environment escapes (needs the A4 systemd scope); times are wall-clock `Date.now()`.

**Tests** (`packages/resource-service/test/`, each in its own `$TMPDIR` state dir, leak check = no process carries the rig's `RESCTL_STATE_DIR`): `grace.test.ts` (alive before / gone after the grace, re-adopt past the original deadline, expired grace not re-adopted, second live owner refused), `run-end.test.ts`, `descendants.test.ts` (double fork + setsid, `env -i`, TERM-ignoring lane, exit codes), `autostart.test.ts`, `daemon-lock.test.ts`, `state.test.ts`, `proc.test.ts`, `reaper-decision.test.ts`, `units.test.ts`, `cli.test.ts`, `no-orchestra-imports.test.ts`. Mutants: `packages/resource-service/mutants/a1.json` run by `packages/resource-service/scripts/mutants.mjs` (exact-once anchors, byte-exact restore, expected-killer name check, leaked-process reaping) — every mutant must turn red a test named in its `expect`. Add `packages/resource-service/mutants/a<n>.json` for each later ticket.

## A3 — `admit` holds a lane when memory or disk is short (#451)

`resctl admit [--timeout <dur>]` (`packages/resource-service/src/verbs/admit.ts:47`) returns at once when **MemAvailable** (`/proc/meminfo`) ≥ `RESCTL_MIN_FREE_MEM` (default `6G`) **and** free disk ≥ `RESCTL_MIN_FREE_DISK` (default `10GiB`); otherwise it WAITS. Exit 0 admitted (stdout `admitted[ after 12s]: free memory 15.2G >= 6G, free disk 272G >= 10G (<path>)`) · 3 `--timeout` reached (`--timeout 0` = look once, never wait) · 2 bad threshold/timeout/`RESCTL_DISK_PATH` · 1 meter unreadable (never admits blind). Sizes use the `units.ts` letters (G = 1024³).

- **Pure decision** `packages/resource-service/src/admission.ts:10` `decide(reading, thresholds)` → `{admit, short[]}`: both must be ≥ their threshold (equal passes); `short` lists each resource below it. The loop `waitForAdmission` (`packages/resource-service/src/admission.ts:60`) takes injected `read`/`thresholds`/`now`/`sleep`, so the unit tests drive rising memory and a lowered threshold on a fake clock.
- **What it prints** (stderr, so `admit && start` keeps stdout clean): `waiting for free memory: 3.2G < 6G; free disk: 4G < 10G (since 2026-11-19T14:24:14.708Z, 12s elapsed)` — at once, then every `RESCTL_ADMIT_REPORT` (30 s) or when the set of short resources changes; it re-measures every `RESCTL_ADMIT_POLL` (2 s) (`packages/resource-service/src/env.ts:29`).
- **Lowering a threshold while waiting** (an env var is fixed at process start): `$RESCTL_STATE_DIR/admit.conf` is re-read every poll — `KEY=VALUE` lines (`RESCTL_MIN_FREE_MEM=3G`, `RESCTL_MIN_FREE_DISK=…`, `#` comments) that OVERRIDE the env; delete the file to fall back to the env. An unusable value is ignored with one warning (`readThresholds`, `packages/resource-service/src/verbs/admit.ts:26`). The other way a wait ends is the free value rising.
- **Disk measured** with `statfs` bavail×bsize (what an unprivileged writer can use) on `RESCTL_DISK_PATH`, default **the state dir** (nearest existing ancestor; `packages/resource-service/src/env.ts:26`, `measuredPath` `packages/resource-service/src/verbs/admit.ts:15`) — the filesystem the service's own state lives on, which is the home filesystem on a default install. An explicit `RESCTL_DISK_PATH` must exist. (Freeze delta: A1's `env.ts` defaulted to `os.homedir()`; env vars `RESCTL_ADMIT_POLL`/`RESCTL_ADMIT_REPORT` and the file `admit.conf` are new.)
- **Not done by admit**: it does not register a lane or hold anything after returning (admission is a gate at the moment of the call, like the app's Admission `src/shared/admission.ts`, which this does not import); a caller starts its lane with `exec` right after.

**Tests**: `packages/resource-service/test/admission.test.ts` (decision for memory / disk / both / boundary, meminfo parse, loop on a fake clock: returns at once, rising memory, lowered threshold, report cadence, timeout), `packages/resource-service/test/admit.test.ts` (real CLI: threshold above free waits + prints, `admit.conf` lowering releases it, disk-only / both, `--timeout` exit 3, defaults on this machine — the expectation is computed from the machine's own readings so the test never skips or flakes on a loaded host). Mutants `packages/resource-service/mutants/a3.json` (18: decision ignores disk/memory, boundary, returns without waiting, thresholds read once, timeout ignored/unclipped, silent / spammy reporting, MemFree, unreadable meter as plenty, conf not re-read, timeout exits 0, wrong default path / thresholds).

## A6 — `--owner auto` finds the Claude Code session; `--max-life` cleans a stuck run (#454)

**`--owner auto`** (`packages/resource-service/src/owner.ts:57` `resolveOwner`, walk `:41` `findClaudeAncestor`): from the CLI's parent up the `/proc` ppid chain, the NEAREST process that is a Claude Code session is the owner (pid + starttime, same identity as a numeric `--owner`). None above → **refused, exit 3**, message names what was looked for and the chain walked; nothing is recorded. A pid or `auto` only — anything else is exit 2. The walk reads through an injectable `ProcView` (`:15` `realProc` is the real one) so the chain is unit-tested on a fabricated process table.

**What a session looks like in `/proc` (measured, CLI 2.1.325, 2026-11-19 — `packages/resource-service/scripts/e2e-claude-owner.mjs` prints it every run).** A real `claude -p` (fake API, node wrapper standing in for the keeper) whose Bash tool ran the CLI:
```
node-22 (resctl)  <  bash (the Bash tool's shell)  <  claude  <  node-22 (keeper/wrapper)  <  …
comm=claude exe=…/.local/share/claude/versions/2.1.325   (cmdline: /home/lmas/.local/bin/claude -p …)
```
- The match is on **`comm == "claude"`** (`packages/resource-service/src/owner.ts:34` `isClaude`; exe basename `claude` also accepted). On a native install the **exe basename is the VERSION** (`2.1.325`), so an exe-only matcher never finds a real session (mutant `A6M05`, rig must-FAIL: exit 3).
- `comm` is the basename of the path the process was `execve`d by: the SDK/keeper launches the `claude` symlink, so `comm` is `claude`; a session started from `versions/2.1.325` directly would show `comm=2.1.325` and `--owner auto` would refuse. An npm install (`node …/cli.js`) is not covered either. Both are limits, not measured here beyond the native symlink.
- The CLI's parent is a shell, never `claude` itself (a `sh -c` that `exec`s the CLI is the one way the parent IS `claude`); the keeper/wrapper node sits ABOVE `claude`, so neither "parent" nor "grandparent" nor "first node" is the session. Nearest-claude wins when sessions nest (a `claude -p` run by an agent owns what it runs).
- A session is its own owner only while alive: kill it and the reaper starts the grace as for any owner (`resctl serve`; the lane dies when the grace ends; measured in the rig).

**`--max-life <duration>`** (`packages/resource-service/src/verbs/run-start.ts:18` `maxLife`): positive duration (`packages/resource-service/src/units.ts` syntax), counted from the call, stored as `maxLifeAt`; `0`, negative, or unparsable → exit 2, nothing recorded. A repeated `run start` with the flag (same owner, or a re-adopt inside the grace) moves the deadline; without the flag the old one stays; a `cleaned` id starts fresh without it. The reaper consumes it (`packages/resource-service/src/reaper.ts:16`, A1): past `maxLifeAt` the run is cleaned **whatever its owner does** — owner alive, no grace — and marked `cleaned` (the owner is untouched).

**Tests / proofs.** `packages/resource-service/test/owner-auto.test.ts` (fabricated tree; real `/proc` with `node` run under the name `claude`: owner = nearest claude, not the shell; nesting; killing it starts the grace; no-claude ancestry → exit 3, NOTHING recorded, via an orphaned CLI because the runner may itself sit under a claude), `packages/resource-service/test/max-life.test.ts` (cleaned while the owner lives and never via a grace; control without the flag untouched; deadline move/keep/adopt; bad values; fresh restart). `packages/resource-service/mutants/a6.json` (12 mutants, `node packages/resource-service/scripts/mutants.mjs --ticket a6`). **Real session** (heavy, ~15 s per arm, not in `pnpm test`): `node packages/resource-service/scripts/e2e-claude-owner.mjs [--proof]` — real `claude` + local fake API + dummy key (zero tokens), scratch `HOME`/`CLAUDE_CONFIG_DIR`, whole run inside `bwrap --unshare-net --unshare-pid --ro-bind / /`; `--proof` re-runs it against the `"rig": true` mutants of `a6.json` (copy of the package, never the tree) — all must turn it FAIL. Last line `E2E-CLAUDE-OWNER: PASS|FAIL|VOID`.
