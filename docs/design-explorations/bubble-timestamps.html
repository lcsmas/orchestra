Structured view — time indication on bubbles

Five options rendered with the real av-* flat-theme tokens (canvas #1a1f26, the green user bubble, rail-less assistant prose). Every AgentEvent already carries an at epoch-ms stamp, so all options are implementable by threading at into RenderMessage at fold time. Hover the bubbles in A and D to see the hover behaviours.

A

Hover-revealed ghost timestamp

Invisible by default. On hover, an absolute time fades in beside the bubble (left of user bubbles, top-right of assistant prose) — same treatment as the existing hover-revealed rewind action.

Pro: zero visual noise; matches an existing pattern. Con: not scannable — you must hunt per-bubble.

Pro: most scannable, great for auditing "when did what happen". Con: costs ~52px of lane width; shifts the whole transcript's geometry.

D

Turn dividers

A hairline divider before each user turn carries the wall-clock time (and the gap since the previous turn when it's large). Individual bubbles stay untouched; per-bubble precision available on hover (as in A).

Pro: groups the transcript into turns — the unit you actually think in; long idle gaps become visible ("+2h"). Con: no per-message granularity without the hover add-on.

E

Turn-anchored: time on the user bubble + turn duration

The time hangs off the user bubble's corner (every turn starts with a prompt), and once the turn ends it gains the elapsed duration — "14:32 · took 3m 40s". Assistant/tool rows stay clean.

Pro: one stamp per turn = low noise but always visible; duration is the number you usually want. Con: corner label slightly crowds the rewind hover row.
