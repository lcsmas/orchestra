# #419 — what a live Bloc HTML costs (built app, contained rig)

Data: `419-bloc-frame-cost.jsonl` (one line per fresh Electron 33.4.11; `valid:false` lines are kept — they are data: see below). Reproduce: `scripts/measure-bloc-frames.sh <built-app-dir> --plan <runs.jsonl> --evidence <file>`; medians: `node scripts/measure-bloc-frames.mjs --summary 419-bloc-frame-cost.jsonl`. The rule that turns it into the shipped figures is re-derived by `src/shared/bloc-frame-cost.test.ts`.

- Measured on the **#415 policy (no network)**; blocs that load libraries over https (D5) will cost more than the figures here.
- Method deviates from #406: 10 s settle + 20 s window (not 30/60), 3 reps; host load average 5–20 during the runs (other agents) — memory is load-insensitive, CPU/latency are not.
- Memory = RSS of the frames process (the one renderer that is not the window's, found by a CPU-burn control on the window) minus the same boot's N=0 reading; PSS of the same pids is in the lines. Controls: N=0 moves the tree < 25 MB; a bloc allocating 40 MB reads +40 MB (`big`).
- `valid:false` busy N=40/50 lines: only 31 frames mounted (the remaining slots stayed beyond the mount margin as 80 px placeholders — the margin working, not a failure); `cell2-srccapoff-4096`/`codesrc-4096`: a 4 MiB reply takes ~340 s to type out at the app's ~12 KB/s typewriter, past the rig's window — **NOT measured**.
- Sibling freeze: 6/6 valid runs, one frames process for all blocs, a looping bloc freezes all 4 siblings (also one in a later reply); the app window answers (round trip 1–2 ms) and keeps 60 Hz rAF. Unmounting the looping bloc does not free them (drive clause M1).
- Builds: rows carry `appHash`. `cfa3046d…` = the margin-only slot (no ceiling) + its `capoff` copy (`29996fc9…`, the 256 KiB cap lifted for the 1 MiB cells). The SHIPPED build adds the ceiling (24) and the layout-effect watchdog; those are gated by the drive (`pnpm run test:bloc-budget`: B1 B2 B3 B7 B8 W1 M1 + 5 must-FAIL arms), not by these cells. N=40 busy has ONE valid row (282 MB, 82 % of a core) — the ceiling rule uses the cells with ≥ 2 valid runs (N=30: 181–189 MB, 35–45 %).
- The window renders at 60 Hz (rAF) with 24–50 live busy blocs and during a sibling loop: the cost is in the frames process, not the window.
- D5 (https libraries in a bloc) was NOT re-measured: by the +50 MB/MiB slope a 200–700 KB library bloc costs several times more per frame than these cells; for tall blocs the 800/1600 px margins, not the ceiling of 24, are the operative bound. Mount churn in a fling (≈3 frame creations per bloc, max 24 simultaneous, 0 long tasks — reviewer's probe) is not costed.
