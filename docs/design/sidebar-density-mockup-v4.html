3 · Does this all work for promoted workspaces?

I was wrong about this, and it's worth stating plainly. I assumed a promoted workspace showed up in the Orchestrators section like a scratch orchestrator does. It does not. The filter is forest.roots.filter(w => w.kind === 'orchestrator') (Sidebar.tsx:1073) — a kind check, not canOrchestrate — and isScratchLike() is false for 'worktree' whatever its flag. So a promoted worktree stays in its own repo section, with its children nested there, and appears in exactly one place. Everything I mocked up until now was the Orchestrators path only.
ChangeHolds for promoted worktrees?
24px single-line rows Yes, and it helps more here. Repo-section rows carry the most metadata (branch + diff + PR + Linear + CI + orch), so they're the ones the flex-basis:100% wrap hurts worst.
Geist + grey rampYes — global, path-independent.
Ring status glyphsYes — .ws-dot is rendered identically by both paths.
Right chevron Yes, but it must be applied to the repo-row renderer too — that's a second code path (Sidebar.tsx:1950+), not the same function. Easy to miss and ship half-done.
C indent (no rail) Yes — both paths use the same --ws-depth mechanism (styles.css:1342), so one formula change covers both.
Dropping the repo-tag pill Careful. In repo sections that pill marks a cross-repo child (crossRepoChild, Sidebar.tsx:2139) — real information, not redundancy. I'd keep it there and drop it only under Orchestrators.
Tree gap Applies to both, since repo sections also stack multiple roots.
One genuine improvement this surfaces: a promoted worktree's only orchestrator cue is the orch pill — there's no marker under the Orchestrators section at all (.orchestrator-pill renders only on repo rows, Sidebar.tsx:2117). So the two kinds of orchestrator look nothing alike today. Reusing the network glyph in both places is a small consistency win the redesign gets almost for free.
Also worth knowing: depth is unbounded (flattenSubtree, Sidebar.tsx:655) — sub-orchestrators nest arbitrarily deep, and today's 16px-per-level formula has no clamp, so a deep chain runs the name off the edge. The ring-a11y-contrast row above is depth 2. With C's larger step I'd clamp the indent after ~3 levels; I'll handle that in the build.
